## 💡 Executive Summary

Developer AI agents typically live isolated inside an individual engineer's terminal or code editor. When production incidents strike, human engineers end up manually copy-pasting alerts, logs, metrics, and terminal outputs across disparate windows.

**SwitchOps AI** bridges this gap. Connected directly into team communication platforms (Mattermost, Slack, Microsoft Teams, Discord) through **Switch**, SwitchOps AI functions as an active operations collaborator in shared incident rooms:
1. **Listens to Team Conversations:** Monitors team channels and ingests incident reports when addressed (`@switchops-ai`).
2. **Autonomous Telemetry Investigation:** Executes authorized diagnostic tools (service health checks, error log queries, connection pool saturation inspection, deployment commit correlation).
3. **Action Plan & Task Generation:** Automatically breaks investigations into structured action plans and incident tracking tasks.
4. **Mandatory Human-in-the-Loop Security Gate:** Consequential actions (such as scaling database pools, rolling restarts of production containers, rollbacks) are **cryptographically intercepted and held** until explicit human authorization is granted in the Command Center.
5. **Channel Transparency & Audit Trail:** Reports verified outcomes and post-mortem summaries back into the Switch room and maintains an immutable audit trail.

## 🛡️ Human Approval & Security Guardrails

SwitchOps AI enforces a strict zero-trust boundary around privileged remediation:
- **No Arbitrary Execution:** The agent never executes arbitrary shell commands or arbitrary code generated by an LLM.
- **Explicit Human Authorization:** Destructive or infrastructure-altering operations (`scale_db_pool_and_restart`, `rollback_deployment`, `flush_redis_cache_cluster`) require human sign-off.
- **Blast Radius Transparency:** The approval modal displays the proposed action, target cluster, consequence summary (e.g. *"Rolling restart of 5 production containers. May cause brief 1-2s connection renegotiation"*), and parameter diffs before approval.
- **Tamper-Evident Audit Trail:** Every incoming message, tool execution, approval decision, and outgoing Switch message is logged with an immutable timestamp and actor identity.

## 🚀 Quickstart & Setup

### Prerequisites
- Node.js v22+ or v24+ (uses native `node:sqlite`)
- npm v10+

### 1. Clone & Install
```bash
git clone https://github.com/sandbox-quantum/switchops-ai.git
cd switchops-ai
npm install
```

### 2. Environment Configuration
Copy `.env.example` to `.env`:
```bash
cp .env.example .env
```

| Variable | Description | Default |
| :--- | :--- | :--- |
| `PORT` | Backend server port | `3001` |
| `CLIENT_PORT` | Frontend Vite port | `5173` |
| `SWITCH_BRIDGE_URL` | Switch Agent Bridge URL (leave empty for local test adapter) | *empty* |
| `SWITCH_AGENT_ID` | Registered Switch Agent ID | `switchops-ai` |
| `SWITCH_API_KEY` | Bearer API token for Switch Agent connection | *empty* |
| `SWITCH_ROOM_IDS` | Comma-separated Switch rooms to claim on connect | `incidents-ops,checkout-team` |
| `GEMINI_API_KEY` | Optional: Gemini API Key (uses Deterministic Engine if unset) | *empty* |
| `OPENAI_API_KEY` | Optional: OpenAI API Key | *empty* |
| `SQLITE_DB_PATH` | Path to SQLite database file | `./data/switchops.db` |

### 3. Run Development Servers
Start both backend and frontend concurrently:
```bash
npm run dev
```
- **Command Center Dashboard:** Open [http://localhost:5173](http://localhost:5173)
- **Backend REST API:** Running on [http://localhost:3001](http://localhost:3001)

## 🎬 How to Run the End-to-End Demo Workflow

To verify the workflow in under 2 minutes:

1. Open the **Command Center** at [http://localhost:5173](http://localhost:5173).
2. Click the **"Trigger P1 Scenario"** button in the top navigation bar.
3. The interface immediately navigates to the **Switch Room Simulator** (`#incidents-ops`):
   - A team member reports: `@switchops-ai Payment checkout is throwing 503 errors and DB connection pool errors in production!`
   - **SwitchOps AI acknowledges** in the room within milliseconds.
   - The agent initiates autonomous diagnostics across health, logs, metrics, and deployment pipelines.
   - Root cause identified: DB connection pool 100% saturated (50/50 connections, 142 waiting) correlating with deployment `v2.14.2`.
   - The agent creates Incident **INC-P1**, spawns 3 tracking tasks, and **halts execution on a Human Approval Gate** for `scale_db_pool_and_restart`.
4. Navigate to the **Approval Queue** tab:
   - Notice the prominent pending approval card with **CRITICAL Risk** level.
   - Inspect the consequences summary and payload parameters.
   - Click **"Approve & Execute Remediation"**.
5. Observe the verified resolution:
   - Remediation executes: connection pool capacity scales to 150; rolling restart completes.
   - P99 latency normalizes to 115ms (HTTP 200 OK).
   - Incident is marked **RESOLVED**.
   - Return to the **Switch Room Simulator** to see the final resolution and post-mortem report posted to the channel!
   - Inspect the **Audit Trail** tab to view the complete immutable event log.
